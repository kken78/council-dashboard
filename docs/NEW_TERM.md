# 改選（任期の切り替わり）への備え

現在のダッシュボードは **第18期（令和5年5月1日〜令和9年4月30日）** を対象にしています。
任期満了に伴う一般選挙（2027年4月ごろ。日程は選挙管理委員会の告示で確認）の前後に、
次の2つを決めて実行する必要があります。

1. **選挙期間中の公開の扱い**（選挙管理委員会・議会事務局と事前に協議）
2. **改選後の切り替え手順**（第19期のダッシュボードの始め方）

> この文書は運用の段取りを整理したもので、公職選挙法上の判断を示すものではありません。
> 選挙期間中の扱いは、必ず選挙管理委員会に確認してください（README「位置づけ」参照）。

---

## 1. 選挙期間中の公開の扱い

### なぜ事前の確認が要るか
ダッシュボードは、議会だより・会議録という公開情報を中立に整理したものです。ただ、議員別のページ
（質問の一覧・写真・会派）は、選挙期間中には候補者の実績紹介のように受け取られる可能性があります。
README のとおり、選挙期間の利用は選挙管理委員会の確認を前提としています。

### 協議で決めておくこと（チェックリスト）
- [ ] 選挙期間中（告示日〜投票日）も公開を続けるか、一時的に公開を止めるか
- [ ] 続ける場合：データの追加・更新を止めるか（新しい号の追加、録画・会議録リンクの更新）
- [ ] 続ける場合：画面に注記を出すか（例：「本サイトは第18期の議会活動の記録で、選挙運動とは関係ありません」）
- [ ] 議員別ページ・写真の扱い（そのまま／一時的に非表示）
- [ ] SNS 等での紹介・告知を控える期間
- [ ] 会議録横断検索（hino-council-search）の扱い（発言の全文検索で、議員別の集計は行っていない）

### 技術的に取れる手段
| やりたいこと | 方法 |
|---|---|
| 公開を一時停止 | Settings → Pages で公開を止める（GitHub Actions のデプロイを無効化）。再開は設定を戻して `build-and-deploy` を手動実行 |
| 更新だけ止める | Actions の `watch`（週1回の確認）を Disable にする。データの追加 PR をマージしない |
| 注記を出す | `src/render_html.py` の冒頭の案内文に1行追加してビルド |
| 議員別ページの写真を隠す | `config.json` の各議員の `photo` を空にしてビルド（氏名表示に切り替わる） |

### 目安のスケジュール
| 時期 | やること |
|---|---|
| 2027年1〜2月 | 選挙管理委員会・議会事務局と上の項目を協議し、方針を決める |
| 告示の前 | 方針に沿って設定を変える（注記・更新停止など） |
| 選挙期間中 | 方針どおり運用。問い合わせ先を明確にしておく |
| 投票日の後 | 下の「2. 改選後の切り替え」へ |

## 2. 改選後の切り替え

### 推奨：期ごとにダッシュボードを分ける
今の作りは「1つの任期を通して見渡す」ことを前提にしています。

- 議員一覧（`config.json` の `members`）から、議席・会派・写真・質問数を表示しています。
- 改選で議員を入れ替えると、退任した議員の過去の質問は残りますが、議員一覧から外れ、写真・会派・議席が出なくなります。

そこで、**第18期は記録として固定し、第19期を新しく始める**のが、作りにも趣旨（任期を通じて何に取り組んだか）にも合っています。

#### 手順
1. **第18期を固定する**
   - 最後の号（2027年3月定例会議分）まで追加したら、タグを打つ：`git tag term-18 && git push origin term-18`
   - 第18期の公開版を残す。次のどちらかを選ぶ。
     - リポジトリを複製して `council-dashboard-term18` として公開する（設定がいちばん単純）
     - `docs/term18/` に第18期のビルド結果をコピーし、第19期のサイトから「第18期の記録」としてリンクする
2. **第19期の設定にする**（`config.json`）
   - `town.council_term`：第19期の任期（例：令和9年5月1日〜令和13年4月30日）
   - `town.term_label`：`第19期`
   - `town.seats`：定数（変更があれば）
   - `members`：新しい議員（`name` は議会だよりの表記、`kana`・`seat`・`kaiha`・`party`・`terms`・`role`・`photo`）
3. **データを第19期の号だけにする**
   - 第18期の `data/issue-NN.json` は `term-18` タグ（と第18期の公開版）に残し、main からは外す
   - `data/videos.json`・`data/minutes_links.json` も第18期分を外す（スクリプトで作り直せる）
   - `scripts/build_video_map.py` の `ISSUE_TO_GIKAI` を第19期の号から書き始める
4. **検査とビルド**
   - `python scripts/validate.py`（議員名が config に無い、などの警告が出ないこと）
   - `python build.py`、表示を確認して公開

#### 1つのサイトで複数の期を見せたい場合
期の切り替え（議員一覧を期ごとに持つ、号に期を持たせる、期の選択 UI）が必要で、
`config.json` の構造・`build.py`・`src/render_html.py` の改修になります。
必要になったら、改選の半年前を目安に着手してください。

### 会議録横断検索（hino-council-search）側
- 発言は氏名で扱っており、議席番号は会議ごとの名簿から付けているため、改選で議席が変わっても**改修は不要**です。
- 週1回の自動取り込みは続けてよい（会議録は公文書の全文で、議員別の集計は行っていない）。選挙期間中の扱いは、上の協議で併せて確認します。
- 統合MCPサーバーは、議会だより側のデータ（`questions.json`）が第19期だけになると、第18期の議会だよりの質問を参照できなくなります。第18期も参照したい場合は、MCP の `DASHBOARD_QUESTIONS_URL` を第18期の公開版のデータに向けた設定を別に用意します。
